title: MCP support for chat agents

superterm's chat can now use tools from MCP servers. Name a server under
`chat.mcp` in config.yaml, and its tools are offered to the model alongside
the chat's own, named after the server: Jina's `search_web` becomes
`jina_search_web`. The model reaches for them when a question needs them,
as a coding agent would.

In the clip, superterm runs in a Slicer VM with two servers configured: Jina
over HTTP for web search, and `mcp-server-git` started locally over stdio.
After a restart, one chat searches the web for SlicerVM, then asks git what
is uncommitted in a project, with DeepSeek V4 Flash answering both.

```yaml
chat:
  mcp:
    jina:
      url: https://mcp.jina.ai/v1
      token_file: ~/.superterm/jina.key
      tools: [search_web, read_url]
    git:
      command: [mcp-server-git, --repository, ~/billing-api]
```

- `url` reaches a remote server over streamable HTTP, with `headers` and a
  bearer from `token_file`; `command` starts a local server and speaks to
  it over stdio.
- `tools` offers only the tools you name. Every tool's description is sent
  with each turn, so a short list keeps the prompt small.
- A server that is down is retried in the background, and a local server
  that dies is started again on its next call.
